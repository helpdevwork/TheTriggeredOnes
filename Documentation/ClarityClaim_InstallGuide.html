Software Install 01

.NET 10 SDK

The .NET SDK is the compiler, runtime, and toolchain for your C# backend. Without this, you cannot build or run the ASP.NET Core Web API. Install this first before anything else.

1
Download .NET 10 SDK
dotnet.microsoft.com — free, official Microsoft download

Open your browser and go to:

https://dotnet.microsoft.com/en-us/download/dotnet/10.0

On the page, under SDK (not Runtime), click the Windows x64 Installer button. This downloads a file named something like dotnet-sdk-10.x.x-win-x64.exe — approximately 200MB.

SDK vs Runtime: Download the SDK, not the Runtime. The SDK includes everything — the runtime is bundled inside it. If you download only the Runtime, you will not be able to compile code.

2
Run the installer
Standard Windows installer — takes about 3 minutes

Double-click the downloaded .exe file. The installer will show a wizard. Click through the defaults — no configuration is needed. It installs to C:\Program Files\dotnet\ automatically and adds itself to your system PATH.

When the installer finishes, close and reopen any open terminal windows so the PATH update takes effect.

3
Verify the install
Open a new terminal — PowerShell or Command Prompt
✓ Verification Command
dotnet --version

You should see a version number starting with 10. — for example 10.0.x. If you see a version number starting with 8 or 9, the old version is still taking priority — restart your machine and try again.

# Also verify the SDK list dotnet --list-sdks # Expected output: 10.0.x [C:\Program Files\dotnet\sdk]
Software Install 02

Node.js 22 LTS

Node.js is required to run the React frontend development server (Vite). It also installs npm, which manages all frontend JavaScript packages. The backend does not use Node — it's purely for the UI.

1
Download Node.js 22 LTS
nodejs.org — always use the LTS version, not Current

Go to:

https://nodejs.org/en/download

Select LTS (Long Term Support) — currently version 22. Click Windows Installer (.msi) 64-bit. Downloads approximately 30MB.

LTS not Current: Always use the LTS version for development work. The "Current" version has experimental features and is less stable. Node 22 LTS is what you want.

2
Run the installer
Accept all defaults — takes about 2 minutes

Run the .msi file. Accept the license agreement. Leave all install options at their defaults — this includes npm (the package manager) and adding Node to your PATH automatically. Do not change the install directory.

On the "Tools for Native Modules" screen — leave the checkbox unchecked unless you know you need it. It is not required for this project and would trigger a large additional download.

3
Verify the install
Open a new terminal after install
✓ Verification Commands
node --version # Expected: v22.x.x npm --version # Expected: 10.x.x or higher

NuGet Packages — Backend

Installing Backend NuGet Packages

NuGet packages are installed per project using the dotnet CLI or Visual Studio's NuGet manager. First create your backend project, then add these packages. All commands run in your terminal from inside the project folder.

1
Create the ASP.NET Core Web API project
Run this once to scaffold the backend project
# Create a new folder for the project and navigate into it mkdir ClarityClaim.Api cd ClarityClaim.Api # Scaffold a new ASP.NET Core Web API project dotnet new webapi -n ClarityClaim.Api --framework net10.0 cd ClarityClaim.Api # Verify it builds before adding any packages dotnet build # Should output: Build succeeded.
2
Install all NuGet packages — one command
Copy and run this entire block in your terminal
# Vector store abstraction layer dotnet add package Microsoft.Extensions.VectorData.Abstractions # In-memory vector store provider (no Docker, no external process) dotnet add package Microsoft.SemanticKernel.Connectors.InMemory --prerelease # AI abstraction layer — for embedding generation via LM Studio dotnet add package Microsoft.Extensions.AI # PDF text extraction — reads NCD/LCD policy PDFs for RAG indexing dotnet add package PdfPig # Whisper.net — C# bindings for local Whisper speech-to-text dotnet add package Whisper.net # JSON serialization — faster than built-in for our use case dotnet add package System.Text.Json

Note on --prerelease: The InMemory connector requires the --prerelease flag because the GA implementation is rolling out across providers. This is safe to use — it is the official Microsoft package, just in active release cycle. No stability risk for a hackathon.

3
Verify all packages installed
Check the .csproj file to confirm all references are there
dotnet list package

You should see all 6 packages listed. Then build once more to confirm no dependency conflicts:

dotnet build # Must still say: Build succeeded.

What each package does in plain English

📦
Microsoft.Extensions.VectorData.Abstractions
The interface contract for vector stores. Defines IVectorStore, VectorStoreCollection, and the attributes you put on your C# classes ([VectorStoreKey], [VectorStoreVector]). Does nothing on its own — needs a provider (item below).
🧠
Microsoft.SemanticKernel.Connectors.InMemory
The actual vector store that runs in RAM. Stores the NCD/LCD policy embeddings as vectors during the app session. No setup, no external process, no Docker. Re-indexes from PDFs every time the app starts — which is fine for a hackathon.
🤖
Microsoft.Extensions.AI
Provides IEmbeddingGenerator — the standard interface for generating text embeddings. You configure it to call the Nomic Embed model running in LM Studio at localhost:1234. Same interface would work with any other embedding provider later.
📄
PdfPig
Reads PDF files and extracts their text content. Used in the RAG indexing script to extract text from the NCD/LCD policy PDFs before chunking and embedding them. Pure .NET — no native dependencies.
🎙️
Whisper.net
C# bindings for OpenAI's open-source Whisper model via whisper.cpp. Transcribes audio files to text entirely on-device. No API key, no cloud, no Python needed. Requires the runtime package below and a model weights file.
NuGet Packages — Whisper.net Runtime

Whisper.net CUDA Runtime

Whisper.net needs a native runtime package to do actual inference. Since your machine has a GPU, use the CUDA runtime — it runs transcription significantly faster than the CPU runtime. This is a separate NuGet package from Whisper.net itself.

1
Install the CUDA runtime for Windows
GPU-accelerated Whisper transcription — much faster than CPU
# GPU runtime — use this since your machine has a CUDA-capable GPU dotnet add package Whisper.net.Runtime.Cuda.Windows

If you hit a CUDA version conflict: If your GPU driver supports CUDA 12 but not 13, use Whisper.net.Runtime.Cuda12.Windows instead. To check which CUDA version your machine supports, run nvidia-smi in your terminal and look at the "CUDA Version" in the top-right corner of the output.

CPU fallback: If you want to avoid CUDA entirely, use dotnet add package Whisper.net.Runtime instead. It will be 3–5x slower for transcription but works without any GPU dependency. For a 45-second pre-recorded demo clip, even CPU Whisper completes in under 30 seconds.

2
Download the Whisper medium model weights
The actual AI model file — ~1.5GB download, one time only

Whisper.net needs the Whisper model weights file to function. Download the medium model — the best balance of accuracy for clinical terminology vs. speed.

# Option 1: Download directly via browser https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-medium.bin # Option 2: Download via PowerShell (run in terminal) Invoke-WebRequest -Uri "https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-medium.bin" -OutFile "ggml-medium.bin"

Save this file to your project folder at ClarityClaim.Api/Models/ggml-medium.bin. The backend code will reference this path when initialising Whisper.net at startup.

File size: The medium model is approximately 1.5GB. Download this before the hackathon on a good internet connection — do not attempt to download it on hackathon day Wi-Fi.

Why not large-v3? The large-v3 model (3.1GB) is more accurate but noticeably slower. For a pre-recorded 45-second demo clip, medium is perfectly adequate and processes in under 15 seconds on GPU. Large-v3 would take 25–40 seconds for the same clip.

Frontend Setup

React Frontend — Vite + Tailwind

The frontend is scaffolded with a single command. Node.js must be installed first. This creates all the boilerplate React project structure and configures Tailwind CSS for styling.

1
Scaffold the React project
Run from the root of your project — not inside the API folder
# Navigate to your project root (one level above ClarityClaim.Api) cd .. # Create the React frontend project npm create vite@latest clarity-claim-ui -- --template react # Navigate into the new frontend folder cd clarity-claim-ui # Install all base dependencies npm install
2
Install Tailwind CSS
Utility-first CSS framework for fast UI building
# Install Tailwind and its peer dependencies npm install -D tailwindcss postcss autoprefixer # Initialise Tailwind config file npx tailwindcss init -p

After running init, open the generated tailwind.config.js and replace the content array with:

// tailwind.config.js content: ["./index.html", "./src/**/*.{js,jsx,ts,tsx}"]

Then open src/index.css and replace its entire contents with:

@tailwind base; @tailwind components; @tailwind utilities;
3
Install Axios for API calls
HTTP client for calling the .NET backend
npm install axios
4
Verify the frontend runs
Should open a browser tab at localhost:5173
npm run dev # Expected output: # VITE v5.x ready in 300ms # ➜ Local: http://localhost:5173/

Open http://localhost:5173 in your browser. You should see the default Vite + React starter page. Installation is complete.

Data Download 02

HAPI FHIR Patient Cache

Run these four API calls once before the hackathon and save the responses as JSON files. The backend will serve from these files during the demo — meaning the FHIR integration works even when the internet is disconnected.

1
Make the four FHIR API calls via PowerShell
Run from anywhere — just needs internet access
# Create the data directory first mkdir ClarityClaim.Api\Data\FHIR # Patient demographics Invoke-WebRequest -Uri "https://hapi.fhir.org/baseR4/Patient/592" -OutFile "ClarityClaim.Api\Data\FHIR\patient.json" # Existing conditions / diagnoses Invoke-WebRequest -Uri "https://hapi.fhir.org/baseR4/Condition?patient=592" -OutFile "ClarityClaim.Api\Data\FHIR\conditions.json" # Current medications Invoke-WebRequest -Uri "https://hapi.fhir.org/baseR4/MedicationRequest?patient=592" -OutFile "ClarityClaim.Api\Data\FHIR\medications.json" # Allergies Invoke-WebRequest -Uri "https://hapi.fhir.org/baseR4/AllergyIntolerance?patient=592" -OutFile "ClarityClaim.Api\Data\FHIR\allergies.json"

Patient ID 592: Confirm this patient ID returns valid data before the hackathon by opening the URL in your browser. If Patient 592 doesn't exist on the test server at the time, pick any valid patient ID from the HAPI public server — browse https://hapi.fhir.org/baseR4/Patient?_count=10 to find active test patients and use their ID consistently across all four calls.
