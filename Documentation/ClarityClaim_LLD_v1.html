5-project .NET solution + 1 React frontend. Each project has one responsibility. No circular dependencies. Domain has no references to anything — everything references Domain.

Section 03

Development Best Practices

BP-01 — Always Async

Every I/O method must be async/await

Every call to LM Studio, FHIR, Whisper, and the vector store is I/O. Never block with .Result or .Wait(). All service methods return Task<T>. This keeps the ASP.NET thread pool free during the 20–30 second model inference wait.

BP-02 — Typed JSON Only

All LLM responses deserialised into typed classes

Never pass raw LLM string output to the frontend. Always deserialise into a C# record with System.Text.Json. Wrap every deserialisation in try/catch. If parsing fails, serve the pre-generated fallback JSON — never let a parse error reach the UI during a demo.

BP-03 — Interface-First

Code to interfaces, not concrete classes

Every infrastructure service implements an interface defined in Domain. ILanguageModelClient, ITranscriptionService, IVectorStoreService, IFhirService. Register interfaces in DI. Services never new up infrastructure — they receive via constructor injection only.

BP-04 — Fallback First

Pre-generate all demo outputs before hackathon

Save the SOAP note, validation result (74%), fixed validation (93%), and patient summary as JSON files in /Data/Fallbacks/. If any live inference call takes >45 seconds or throws, the service silently returns the fallback. Add a boolean _useFallback flag in config for instant toggle.

BP-05 — Temperature = 0.1

Low temperature on all clinical inference calls

Use temperature: 0.1 for all SOAP and validation calls. Clinical reasoning needs determinism, not creativity. Use temperature: 0.3 only for the patient summary (Llama 1B) where a slightly varied but warm tone is acceptable.

BP-06 — No Phi-2

Phi-2 is excluded from all tasks

phi-2 Q2_K has a 2048-token context limit (shorter than a single SOAP note) and Q2 quantisation degrades clinical accuracy unacceptably. It must not be registered in DI or called from any service. If it appears in the model list, skip it.

BP-07 — Chunk at 1400 Tokens Max

Nomic Embed has a hard 2048-token limit per call. Always chunk PDF text at 1400 tokens with 150-token overlap. Use tiktoken (not character count) to measure token length. Exceeding the limit silently truncates the embedding and degrades RAG retrieval quality.

BP-08 — CORS Locked to localhost:5173

Configure CORS in Program.cs to allow only http://localhost:5173. This prevents any accidental cross-origin call during the demo and signals security awareness to judges. Never use AllowAnyOrigin().

BP-09 — One HttpClient per Service

Register HttpClient via IHttpClientFactory with named clients in DI: "lmstudio" and "fhir". Never create new HttpClient() inline — socket exhaustion will crash the backend during repeated demo calls.

BP-10 — SSE for Transcript Streaming

The transcript endpoint must use Server-Sent Events (SSE), not WebSockets. Set Content-Type: text/event-stream. SSE is simpler, one-directional, and works through any proxy. The frontend uses the browser's native EventSource API — no library needed.

Whisper STT Service

Wraps Whisper.net for local on-device transcription. Uses the medium GGML model at /Data/Models/ggml-medium.bin. CUDA runtime for GPU acceleration. Model loaded once at startup.

// ClarityClaim.Infrastructure/Whisper/WhisperTranscriptionService.cs public class WhisperTranscriptionService : ITranscriptionService, IAsyncDisposable { private WhisperFactory? _factory; private WhisperProcessor? _processor; private readonly string _modelPath; public WhisperTranscriptionService(IConfiguration config) => _modelPath = config["Whisper:ModelPath"] ?? "Data/Models/ggml-medium.bin"; // Called once during DI startup via IHostedService warm-up public async Task InitialiseAsync() { _factory = WhisperFactory.FromPath(_modelPath); _processor = await _factory.CreateBuilder() .WithLanguage("en") .WithThreads(4) .BuildAsync(); } public async Task<TranscriptResponse> TranscribeAsync( string audioFilePath, CancellationToken ct = default) { if (_processor is null) await InitialiseAsync(); var segments = new List<TranscriptSegment>(); await foreach (var seg in _processor!.ProcessAsync(audioFilePath, ct)) { segments.Add(new TranscriptSegment( seg.Start.TotalSeconds, seg.End.TotalSeconds, seg.Text.Trim() )); } var fullText = string.Join(" ", segments.Select(s => s.Text)); return new TranscriptResponse(fullText, segments); } public async ValueTask DisposeAsync() { if (_processor is not null) await _processor.DisposeAsync(); _factory?.Dispose(); } }

FHIR Service

Queries the HAPI FHIR R4 public test server for patient context. Serves from local JSON cache (/Data/FHIR/) when offline — which is always during the demo. Cache is populated once before the hackathon.

// ClarityClaim.Infrastructure/Fhir/FhirService.cs public class FhirService : IFhirService { private readonly HttpClient _http; private readonly ILogger _logger; private readonly string _cacheDir; private const string HAPI_BASE = "https://hapi.fhir.org/baseR4"; public async Task<FhirPatientContext> GetPatientContextAsync( string patientId, CancellationToken ct = default) { // Always try cache first — demo runs offline var cachePath = Path.Combine(_cacheDir, $"patient_{patientId}.json"); if (File.Exists(cachePath)) { var cached = await File.ReadAllTextAsync(cachePath, ct); return JsonSerializer.Deserialize<FhirPatientContext>(cached)!; } // Live call — fetch, parse, write cache for future use try { var patient = await FetchFhirResourceAsync($"Patient/{patientId}", ct); var conditions = await FetchFhirResourceAsync($"Condition?patient={patientId}", ct); var meds = await FetchFhirResourceAsync($"MedicationRequest?patient={patientId}", ct); var allergies = await FetchFhirResourceAsync($"AllergyIntolerance?patient={patientId}", ct); var context = ParseFhirBundle(patient, conditions, meds, allergies); await File.WriteAllTextAsync(cachePath, JsonSerializer.Serialize(context), ct); return context; } catch (Exception ex) { _logger.LogWarning(ex, "FHIR live call failed, returning empty context"); return new FhirPatientContext { PatientId = patientId }; } } private static FhirPatientContext ParseFhirBundle( JsonDocument patient, JsonDocument conditions, JsonDocument meds, JsonDocument allergies) { // Extract name from Patient resource name[0].text var name = patient.RootElement .GetProperty("name")[0] .GetProperty("text").GetString() ?? "Unknown"; var dob = patient.RootElement.GetProperty("birthDate").GetString() ?? ""; var gender = patient.RootElement.GetProperty("gender").GetString() ?? ""; // Extract conditions — entry[].resource.code.text var conditionList = conditions.RootElement .GetProperty("entry").EnumerateArray() .Select(e => e.GetProperty("resource") .GetProperty("code") .GetProperty("text").GetString() ?? "") .Where(s => !string.IsNullOrEmpty(s)) .ToList(); // Similar extraction for medications and allergies return new FhirPatientContext { PatientId = patient.RootElement.GetProperty("id").GetString()!, FullName = name, DateOfBirth= dob, Gender = gender, Conditions = conditionList }; } }

set; } = string.Empty; // "L34220" [VectorStoreData] public int Page { get; set; } [VectorStoreVector(768)] // Nomic v1.5 produces 768-dim embeddings public ReadOnlyMemory<float> Embedding { get; set; } } public class PolicyVectorStoreService : IVectorStoreService { private readonly VectorStoreCollection<string, PolicyVector> _collection; private readonly LmStudioClient _lm; private const int MAX_CHUNK_TOKENS = 1400; public PolicyVectorStoreService(LmStudioClient lm) { _lm = lm; var store = new InMemoryVectorStore(); _collection = store.GetCollection<string, PolicyVector>("ncd_lcd_policies"); _collection.EnsureCollectionExistsAsync().GetAwaiter().GetResult(); } public async Task IndexDocumentAsync(string text, string source, string lcdId) { var chunks = ChunkText(text, MAX_CHUNK_TOKENS, overlapTokens: 150); foreach (var (chunk, idx) in chunks.Select((c, i) => (c, i))) { var embedding = await _lm.EmbedAsync(chunk); await _collection.UpsertAsync(new PolicyVector { Text = chunk, Source = source, LcdId = lcdId, Page = idx, Embedding = new ReadOnlyMemory<float>(embedding) }); } } public async Task<List<PolicyChunk>> RetrieveAsync(string query, int topK = 3) { var queryEmbedding = await _lm.EmbedAsync(query); var results = await _collection .SearchAsync(new ReadOnlyMemory<float>(queryEmbedding), topK) .ToListAsync(); return results .Select(r => new PolicyChunk(r.Record.Text, r.Record.Source, r.Record.LcdId, r.Record.Page)) .ToList(); } // Simple word-boundary chunking with overlap private static List<string> ChunkText(string text, int maxTokens, int overlapTokens) { // Approximate: 1 token ≈ 4 characters. Use tiktoken in production. var approxChunkSize = maxTokens * 4; var approxOverlapSize = overlapTokens * 4; var chunks = new List<string>(); var start = 0; while (start < text.Length) { var end = Math.Min(start + approxChunkSize, text.Length); var chunk = text[start..end]; chunks.Add(chunk); start += approxChunkSize - approxOverlapSize; } return chunks; } }

Validation Service — PS 39

The core of the product. Retrieves relevant NCD/LCD policy chunks via RAG, calls Qwen Instance 2 (240K) for primary gap analysis, Gemma4 for independent second-pass, merges scores with weighted average (0.6 / 0.4), and returns a full scorecard.

// ClarityClaim.Services/ValidationService.cs public class ValidationService { private readonly ILanguageModelClient _lm; private readonly IVectorStoreService _vs; public async Task<ValidationResponse> ValidateAsync( ValidateDocumentRequest req, CancellationToken ct = default) { try { // Step 1: RAG retrieval — query using ICD codes + "medical necessity" var query = $"{string.Join(" ", req.Icd10Codes)} medical necessity documentation requirements"; var chunks = await _vs.RetrieveAsync(query, topK: 3); var policyContext = BuildPolicyContext(chunks); var soapText = SoapToText(req.SoapNote); // Step 2: Run Qwen and Gemma in parallel for speed var qwenTask = RunQwenValidationAsync(soapText, policyContext, ct); var gemmaTask = RunGemmaValidationAsync(soapText, policyContext, ct); await Task.WhenAll(qwenTask, gemmaTask); var qwenResult = qwenTask.Result; var gemmaResult = gemmaTask.Result; // Step 3: Merge — Qwen weighted 0.6, Gemma 0.4 var mergedScore = (int)Math.Round( qwenResult.ApprovalScore * 0.6 + gemmaResult.ApprovalScore * 0.4 ); // Step 4: Flag disagreements — where models differ by >20 points var flags = Math.Abs(qwenResult.ApprovalScore - gemmaResult.ApprovalScore) > 20 ? ["Models disagree significantly — human review recommended"] : (List<string>)[]; return new ValidationResponse( new ValidationResult { ApprovalProbability = mergedScore, Gaps = qwenResult.Gaps, Fixes = qwenResult.Fixes, PolicyReferences = chunks.Select(c => $"{c.Source} p.{c.Page}").ToList(), PassingCriteria = qwenResult.PassingCriteria, HumanReviewFlags = flags }, FromFallback: false ); } catch (Exception ex) { return new ValidationResponse(LoadFallbackValidation(), FromFallback: true); } } private async Task<LlmValidationOutput> RunQwenValidationAsync( string soapText, string policyContext, CancellationToken ct) { var raw = await _lm.CompleteAsync( LmStudioClient.Models.QWEN_240K, // 240K context fits full policy docs VALIDATION_SYSTEM_PROMPT, BuildValidationUserPrompt(soapText, policyContext), temperature: 0.1f, maxTokens: 3000, ct: ct ); return ParseValidationJson(raw); } private async Task<LlmValidationOutput> RunGemmaValidationAsync( string soapText, string policyContext, CancellationToken ct) { var raw = await _lm.CompleteAsync( LmStudioClient.Models.GEMMA, VALIDATION_SYSTEM_PROMPT, BuildValidationUserPrompt(soapText, policyContext), temperature: 0.1f, maxTokens: 2000, ct: ct ); return ParseValidationJson(raw); } private const string VALIDATION_SYSTEM_PROMPT = """ You are a medical billing compliance specialist. Error Handling Strategy

LLM Inference Errors

Pattern: Always wrap in try/catch in the Service layer. Never throw to the Controller. Return FromFallback: true and serve the pre-generated JSON from /Data/Fallbacks/. Log the error with ILogger.LogWarning — not Error, because this is expected during demos.

JSON Parse Errors

Pattern: Strip markdown fences before deserialising. If JsonSerializer.Deserialize throws, log raw response at Debug level and return fallback. Never expose the raw LLM string in an API error response — it may contain PHI from the transcript.

FHIR Unavailable

Pattern: Cache-first always. If cache file exists, serve it. If cache is missing and live call fails, return an empty FhirPatientContext with the PatientId populated. Never block the SOAP generation — it can run without FHIR context.

Frontend Error Boundary

Pattern: Wrap each screen in a React Error Boundary. If a screen crashes, show the pre-rendered screenshot fallback. Never let the entire app white-screen during a judge presentation. The fallback screenshots must be loaded as static assets in /public/fallbacks/.
